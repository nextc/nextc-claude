# Changelog

All notable changes to nextc-claude are documented here, grouped by date.

## 2026-07-02

Rule additions distilled from a cross-session UI/layout failure (a screen "verified" via `flutter analyze` + tests — proxies for code correctness — while its actual rendered layout was never checked).

### Added
- **`rules/nextc-claude/verify-before-claim.md`** — new trigger #9: judging a visual/UI deliverable (layout, spacing, positioning, "looks right") requires rendering it this session. The rendered screen is the authoritative source for appearance, the running app for interaction; a green analyze/typecheck/lint/test is a proxy for code correctness, not for pixels. Render current + target together, make one change, re-render.
- **`rules/nextc-claude/ui-ux-design.md`** — new principle #7 "Layout is scientific; structure before polish; use the design skill": ground layout in a measured system (spacing/type scale, alignment grid, rendered measurements) rather than eyeballing; get structure/position correct before motion/color/finish; use the installed design skill (e.g. `ui-ux-pro-max`) for design tasks. Matching Enforcement bullets added.

### Changed
- **`rules/nextc-claude/practices.md` → Think Before Coding** — two new guards: a vague instruction ("make it great", "clean this up", "fix it") is not a mandate to guess — surface your reading and confirm first; and "spending reasoning tokens is not thinking" — establish *which* problem you're solving before optimizing an artifact. New **"Substance Over Ceremony"** section: the rule-set's overhead (context blocks, docs, memory, changelog, lint gates) serves the deliverable and must never crowd out verifying the real output.
- **`flutter-build` / `unity-build` — standard `build/` artifact location.** The final APK/IPA is now **moved to the build-dir root** (`build/` for Flutter, `Builds/` for Unity) instead of being left nested in `build/app/outputs/apk/release/` · `build/ios/ipa/` · `Builds/Android/` · `Builds/iOS/ipa/`. Updated the Phase-4 / Step-8 placement step (`mv` to the root, one canonical file per platform, covering the flutter / xcodebuild / fastlane output paths), the `MODE: full` fallback in each builder agent, and every report-table Path column. Supersedes the prior CRITICAL "rename in the original output directory, never move" rule in both builders.

### Added
- **`rules/nextc-claude/stop-and-diagnose.md` (NEW rule #14, CRITICAL)** — when something is not as expected (a command fails, output is wrong, a build/upload/deploy errors), STOP and diagnose before repeating or varying the action: no blind retries, read the full evidence before naming a cause, give irreversible/outward-facing actions a fresh approval gate every time (a prior "proceed" never authorizes a retry) and confirm whether the "failure" is even real, change one variable at a time, and escalate to "wrong approach" rather than looping. Distilled from a session that retried a TestFlight upload repeatedly on stale approval while asserting unread causes — the uploads had actually reached Apple; a DNS drop in post-upload polling was the real error. Composes with `verify-before-claim.md` and `safety.md`.

### Removed
- **`rules/nextc-claude/minimal-fix-scope.md`** — removed at the user's direction. Synced all 9 references so nothing dangles: dropped it from the `CLAUDE.md`/`README.md` rule lists (count unchanged at 14 — the new `stop-and-diagnose` rule takes its slot), and removed/reworded the cross-links in `bug-fix`, `adversarial-review`, `a11y-architect`, and the `latest-spec-wins` / `practices` / `testing-policy` / `agentic-security` rule files.

### Fixed
- **Agents couldn't complete the team-shutdown handshake — added `SendMessage` to every agent's `tools:`.** In practice the `tools:` allowlist gates coordination tools (contrary to the CC docs' "always available" claim): a teammate whose list omits `SendMessage` (e.g. `flutter-builder`/`unity-builder`, tools = Read/Write/Edit/Bash/Glob/Grep/AskUserQuestion) physically can't reply `shutdown_approved`, so after finishing it parks as idle and re-emits idle pings while `shutdown_request` is a no-op. Added `SendMessage` to all 50 agent definitions that were missing it (both inline-array and multi-line `tools:` formats; `ui-ux-developer` already had it; the 4 `references/` templates have no `tools:` field). Corrected the now-disproven claim in `team-feature-dev` SKILL (line ~248) that this is "not a tooling constraint," and added an `agents.md` enforcement rule so no new agent ships without `SendMessage`.

## 2026-07-01

### Added
- **Fastlane signing + env resolution for iOS builds (`flutter-build` and `unity-build`)** — the build skills/agents now read the project's fastlane setup and fill the environment variables the lanes need, modeled on the nextc `setup-ios-signing.sh` generator (which is config-file-based, not dotenv-based). Behavior:
  - **Preflight** (mirrors the generator's own): before running a lane, verify the signing config exists at `~/.fastlane-nextc/config/teams.json` (or `$IOS_SIGNING_CONFIG`); if missing, STOP with `setup-ios-signing.sh <team> <bundle-id>` instructions rather than failing mid-build. Best-effort warn if the team's `~/.fastlane-nextc/private-keys/AuthKey_<id>.p8` is absent.
  - **Auto-filled env** (inline prefix to the `fastlane` command only, never persisted/logged): `IOS_SIGNING_CONFIG` (only when non-default), `FL_CHANGELOG` (from the build's curated "What's new" for the `testflight` lane, so external testers get real release notes), `TESTFLIGHT_GROUPS` (on override). `MATCH_PASSWORD` is deliberately never set — the Fastfile self-seeds it from the config.
  - **Generic fallback** for non-nextc Fastfiles: discovers `ENV['X']` references across `Fastfile`/`Appfile`/`Matchfile`, unions with `.env`/`.env.default` keys, relies on fastlane's automatic dotenv loading, and warns on anything still unresolved (no secret prompting — secrets belong in `~/.fastlane-nextc`, not the repo).
  - New "Fastlane Signing & Env" section in `flutter-builder.md`; new "iOS via Fastlane (sign-only)" section in `unity-build/SKILL.md`. Added a `Changelog` spawn field (Flutter) so the testflight lane can receive the approved What's-new.
- **Full fastlane iOS build path for `unity-build`** — Unity iOS builds can now sign + export via the nextc fastlane lanes (`build_adhoc`/`build_appstore`/`release_testflight`) instead of raw `xcodebuild`. The generator already supports Unity as a **sign-only** path (fastlane at the project root, operating on the `Builds/iOS/Unity-iPhone.xcodeproj` Unity regenerates each build). When `fastlane/Fastfile` exists at the project root, the skill runs the lane (on the main thread, per the threading rule) in place of the `ExportOptions.plist` + `xcodebuild archive` + `exportArchive` steps; when absent, the xcodebuild path is unchanged. Lane selection mirrors `flutter-build`. The "Team ID in ProjectSettings" guard is relaxed on the fastlane path (the `Appfile` carries `team_id` and `match` signs); artifact verification/rename now handle gym's project-root IPA output. The `unity-builder` `MODE: full` fallback gained the same fastlane branch so fallback behavior matches.

### Security
- Documented and enforced (in build skills/agents) that fastlane signing secrets (`teams.json` `match_password`, the `.p8` key) live only in `~/.fastlane-nextc/` and are never read into logs, reports, or commits, and that these build-time credentials are distinct from `--dart-define-from-file` / the `Assets/` bundle guard — they authenticate signing/upload and never enter the app binary.

## 2026-06-17

### Added
- **`rules/nextc-claude/skill-authoring.md` (NEW global rule #14)** — Skill Discovery Optimization (SDO) principle adapted from obra/Superpowers. A skill's `description` field must state purpose + trigger only, never enumerate the internal workflow, phases, or agents invoked — agents follow a workflow-summary description in the body and skip the skill body when reading (because the description has already been evaluated). Codifies the observation that oversaturated descriptions undermine discoverability and trigger mis-targeting. Includes a "match the form to the failure" table: missing skill from listing (over-long description), wrong skill selected (description doesn't match intent), undercalling (discovery blocked by off-putting jargon), overcalling (description promises more than delivery). Applies the two-field frontmatter convention (`description` + `when_to_use`) and cross-references the skill-creator `run_loop.py` description-optimization pipeline used in the May 2026 audit.
- **`nextc-ecc/skills/adversarial-review/SKILL.md` (NEW skill, `/adversarial-review`)** — Two independent reviewers (different models, lenses, no shared context or prior history) must both PASS before high-stakes output ships (deploy, release, architecture, API contract, sensitive data schema change). At most 3 fix-and-converge rounds with fresh reviewers each round; if converged reviewers still fail, escalate to a 3rd tiebreaker or reject. Adapted from affaan-m/ecc santa-method (Ronald Skelton's original work). Wired to our `Agent()` model conventions: spawn reviewers as independent `Agent(model: "sonnet")` workers with orthogonal vantage points (e.g., performance + security, or API + UX), feed each the artifact + author's intent, run in parallel, collect verdicts async. Integration notes for `code-reviewer`, `verification-loop`, and `council` skills for chainable review gates. Rationale: a single review voice misses blind spots that orthogonal experts catch.
- **`nextc-ecc/skills/production-audit/SKILL.md` (NEW skill, `/production-audit`)** — Local-evidence 0-100 production-readiness audit with ship/block bands and hard score caps. Scoring: baseline 100, capped at 69 if any hard blocker found (missing auth, non-idempotent webhooks, unsafe migrations, exposed secrets, no rollback plan), capped at 84 if CI not green OR no E2E test coverage. Uses only local proofs (open files, grep, `git log`, run tests) — no remote scanners, no repo upload, no SaaS. Output: `production-audit.md` with 0-100 score, band (ship/hold/block), gaps per category, and per-gap fix guidance. Adapted from affaan-m/ecc. Complements `/verification-loop` (which verifies build/typecheck/lint/test) by adding deploy-time guardrails.
- **`nextc-core/skills/blueprint/SKILL.md` (NEW skill, `/blueprint`)** — Turns a one-line objective into a cold-start-executable multi-PR/multi-session construction plan at `docs/plans/<slug>.md`. Outputs a structured plan with per-step context briefs (assumptions, Consumes/Produces contracts, error modes), dependency graph, parallel-path detection, and a review gate (planner + architect agents assess feasibility + redundancy before output). Supports plan mutation on subsequent runs (e.g., "after PR #42, replan from Step 5"). Adapted from affaan-m/ecc. Rationale: bridges the gap between a proposal (high-level intent) and a sprint (which assumes the path is already clear). Live blueprints become the handoff artifact between product and engineering.
- **`nextc-ecc/hooks/scripts/loop-scope-guard.js` + registration in `nextc-ecc/hooks/hooks.json` (NEW, 6th hook)** — PreToolUse event, stderr-only, never blocks: detects stuck tool loops (same tool+input >=3 times within a sliding window) and session scope creep (>20 distinct files edited per session). Self-contained, no metrics-bridge or token accounting (cost tracking intentionally NOT ported from affaan-m/ecc). Tunables: `LOOP_THRESHOLD`, `LOOP_WINDOW`, `SCOPE_THRESHOLD`; disable via `LOOP_SCOPE_GUARD=off`. Logs to stderr as a contextual note, no interruption. Use to surface low-momentum runs to the user for course correction mid-session. Documented limitations: only detects tool-invocation loops, not logical infinite loops (e.g. reasoning that never converges).
- **`reference-oss/` (gitignored, NEW)** — Vendored clones of obra/Superpowers and affaan-m/ecc (the two MIT-licensed reference codebases) under `reference-oss/`, with a `reference-oss/update.sh` script to refresh them and `reference-oss/_analysis/` reports. Crediting the source repos inline in each new feature. Gitignored because these are large (~1–2 GiB) and only needed during development/spec-porting; they are not part of the marketplace distribution.

First version of nextc-claude (originally "dotclaude") — a collection of custom agents, rules, and skills for Claude Code.

Core capabilities:
- **Error handling rule** requiring debug-safe logging in every catch block and user-friendly error messages in every UI
- **Flutter localization pipeline** with 5 steps: audit hardcoded strings, harmonize terminology, extract to ARB, translate via OpenAI, and verify translations
- **Flutter build agent** that builds APK/IPA, manages version bumps, renames artifacts, and logs build history
- **ASO pipeline** (v1) with 8 agents for App Store Optimization
- **setup-rules.sh** for symlinking shared rules into any project

All skills and rules were made project-agnostic from the start — no hardcoded paths or domain-specific assumptions.
