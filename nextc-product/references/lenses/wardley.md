# Lens: Wardley Mapping

Source: Simon Wardley.

**Fits when** the product depends on components (data, infrastructure, platforms, content) whose
maturity decides what to build versus reuse. **Skip when** the question is about user demand
only and the build is trivial.

## Method

1. Anchor on the user and their need.
2. List seven to twelve components in the value chain, including non-software ones (data
   licences, content, regulation, community).
3. Place each on the evolution axis: genesis, custom, product, commodity, and give its direction
   of travel. Where a component exists as a product or open dataset, cite the prior-art record.
4. Say which components to build (genesis or custom, and core), which to reuse, and where an
   incumbent's legacy investment is an opening.

## Anti-patterns

- No user-need anchor, so the map becomes an architecture diagram.
- A static snapshot with no direction of travel.
- Building a component that the evidence shows already exists as a product or open source.

## Lens section of the output

Component table (component | stage | direction | evidence); build/reuse/commoditise call per
significant component; the one component that is genuinely genesis, if any.
