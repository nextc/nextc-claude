# nextc-ecc hooks

Registered in `hooks.json`. Claude Code accepts only `matcher`, `hooks`, and `timeout` inside a matcher group (plus one top-level `description`), so the per-hook notes live here.

Two handler fields narrow and harden the gates (both per https://code.claude.com/docs/en/hooks):
- `if` (permission-rule syntax) skips the hook unless a subcommand matches, so the git gates don't start a process on every Bash call. It is best-effort: when Claude Code can't tell what a command runs, the hook runs anyway.
- `onFailure: "block"` (Claude Code v2.1.295+) makes a gate that can't start or crashes block the action instead of letting it through. It is set on all three gates.

| Event | Matcher | Hook | Purpose |
|---|---|---|---|
| PreToolUse | `Bash`, `if: Bash(git *)` | `block-no-verify` | Block git hook-bypass flags (`--no-verify` on commit/push/merge/cherry-pick/rebase/am, `git commit -n`, a `core.hooksPath` override) to protect pre-commit, commit-msg, and pre-push hooks from being skipped. Checks each command in a Bash call on its own words, so `grep -n` next to a `git commit` is allowed; quoted text (`sh -c`, `eval`, `$(...)`) is checked too. Adapted from the `block-no-verify` npm package (MIT). `onFailure: block`. |
| PreToolUse | `Write\|Edit\|NotebookEdit` | `config-protection` | Block modifications to linter/formatter config files (ESLint, Prettier, Biome, Ruff, shellcheck, stylelint, markdownlint, Dart `analysis_options.yaml`, `.editorconfig`) — fix code, not config. The deny message tells a session with no human to ask the user, or to mark the step blocked in an unattended run. Stays active inside `/autopilot` runs on purpose: no human reviews those, so this is one of the few guards left. `onFailure: block`. |
| PreToolUse | `Bash`, `if: Bash(git *)` | `pre-commit-quality` | On each real `git commit` (including `--amend`, `-a`, `git -C dir commit` and `cd dir && git commit`, scanning that directory), scan the content that will land: block (exit 2) on secrets in any text file (Anthropic/OpenAI, GitHub, Slack, Google, Stripe, AWS, private keys, assigned credentials) and `debugger` in code files; warn on console.log and non-conventional subject (heredoc messages are parsed; `fixup!`/`Merge`/`Revert` subjects are skipped). Text that only mentions `git commit` inside quotes, `echo` or a heredoc is ignored. Not parsed: a commit inside `sh -c "..."` or `eval`. No external linters. `onFailure: block`. Disable: PRECOMMIT_QUALITY=off. |
| PostToolUse, PostToolUseFailure | `Edit\|Write\|MultiEdit\|NotebookEdit\|Bash` (failure: `Bash`) | `proof-gate record` | Keeps a per-session ledger of code files edited (prose, images and lockfiles are skipped, as in nextc-hud) and of the checks that ran (`flutter analyze/test`, `tsc`, `npm test/lint`, `go test`, `node --test`, `claude plugin validate`, and the rest of the list copied from nextc-hud's `proof.ts`). A check counts as passed only when its own exit status is the command's: a successful PostToolUse, not piped, not chained with `;`, not in the background, not interrupted. Anything else is recorded as "unseen". A later edit, or a shell edit (`sed -i`, `git checkout`, `--fix`, `--write`), makes earlier checks stale. Each edit is stored with the `agent_id` that made it (none = the main session). Once a check has passed, the next edit starts a fresh list. A lone `&` (backgrounded command) makes a check unseen; `git checkout -b`, `git stash list|show` and anything with `--check` or `--dry-run` are not shell edits. Never blocks; always exits 0. Ledger: `~/.claude/nextc-proof-gate/<session_id>.json` (always under the home folder, `CLAUDE_CONFIG_DIR` is ignored because nextc-hud reads the same path), folder mode 0700, files 0600, pruned after 7 days. Edits under the session's `scratchpad_dir` are skipped (compared by real path, so `/tmp` and `/private/tmp` match). The raw path is kept, so files with spaces, brackets or `~` stay apart; a name with control characters is replaced when the ledger is read, labels outside plain characters are dropped, and only names of ordinary path characters (no backtick, quote, angle bracket, shell operator or newline) are quoted to Claude, the rest counted. |
| Stop | none (not supported) | `proof-gate stop` | When code changed and no check passed since (or a check failed and was not re-run), returns `additionalContext` (non-error feedback) naming the changed files, newest first, and asking Claude to run the checks that cover them and report each command with its result, or say why none applies. It does not run anything itself. Files deleted since their edit are left out. Once per edit set (one more if a check then fails). Lets the turn end when `stop_hook_active` is true, a background subagent or teammate is running (it may still be editing; a background shell command such as a dev server does not count), the last message ends with a question to the user (a heuristic: a trailing `?`), the ledger is missing or unreadable, `PROOF_GATE=off`, or inside an autopilot run (`AUTOPILOT_RUN_DIR`). |
| TaskCompleted | none (not supported) | `proof-gate task` | The same test when a task is marked completed, counting only the edits made by the agent completing it (`agent_id`; none = the main session), but exit 2 with the reason on stderr keeps the task open. Blocks once per agent and edit set, then allows. Stands down only with no ledger, `PROOF_GATE=off` or inside an autopilot run; the running-agent and trailing-question checks apply to Stop alone, because a task is marked done by the agent that did the work. |

`proof-gate` has no `onFailure: block` on purpose: it fails open on any error (debug output with `PROOF_GATE_DEBUG=1`). Every proof-gate handler has `timeout: 10` (seconds). Optional `PROOF_GATE_EXTRA_CHECKS` (a regular expression, at most 200 characters; an invalid one is ignored and logged under `PROOF_GATE_DEBUG`) adds a project's own check command. `tests/proof-gate.test.mjs` fails when its patterns drift from nextc-hud's. When the gate has a ledger for a session, nextc-hud's `proof_followup` stands down so Claude is not asked twice.

## Output contract

The three guard hooks above do not print to stdout. They exit 0 with no output (no decision) or exit 2 with the reason on stderr. (`proof-gate stop` is the one exception: it prints the `additionalContext` JSON.) Per https://code.claude.com/docs/en/hooks, "Exit code 0 with no output means the hook has no decision to report, so the tool call continues through the normal permission flow", and hooks for an event "run in parallel", so there is no pass-through chain that needs the input echoed.

## Removed hooks

`tool-awareness`, `suggest-compact`, `loop-scope-guard`, `fact-force-guard` and `verify-before-claim-scan` were removed after measuring real sessions: they produced output nobody acted on (about 600 stderr lines from tool-awareness; 73 compaction suggestions next to 178 compactions; 68 loop notices that never blocked), or blocked work with a retry that always passed (fact-force-guard: 116 denials, 65% simply re-run unchanged, with false positives on `rm -rf build`, `git checkout -- <file>` and heredoc text, and misses such as `sh -c "rm -rf /"`), or fired rarely and only on common phrases (verify-before-claim-scan: 5 injections in 2,342 Stop events). Destructive commands now get a native human prompt through the `permissions.ask` rules in `settings/user-settings.json` (merged by `setup-rules.sh`).
